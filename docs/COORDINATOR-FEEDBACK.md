# Coordinator corrections and feedback

The coordinator can correct a blocked field, record the reason and rebuild the affected drafts without another model request. Confirming the same value can also resolve an old requested status or unanswered question. Source messages, original model evidence, pending requests and questions remain available in the original record.

The editor can accept custom text in every text field. Dietary, setup, AV and special arrangements can be explicitly confirmed for this event. This is not a global policy change. Invalid dates or counts cannot be saved; an unpriced menu, unknown venue, capacity conflict or unresolved detail still blocks dependent outputs. Confirmed corrections are never automatically marked reviewed.

## Feedback flow

Each editor save stores the changed fields, before/after details, reason and timestamp in the same immutable review snapshot as the corrections. Review saves preserve that history. Concurrent edits use the existing sequence check. Existing older reviews remain readable without migration. New audit entries begin with this feature; older corrections remain visible in the source inspector.

An optional general lesson is limited to 500 characters. Up to five most recent unique enabled lessons are supplied in the next AI request, within the same workspace and restaurant profile. The coordinator can disable a lesson without deleting its audit entry. Only the explicit lesson and field names are sent as memory; the change reason, original source quotes, names, dates and counts are not automatically copied. The lesson guidance says to use current-message evidence and never treat a previous event's facts or confirmations as facts about a new event.

Public and private memory use their existing isolated storage namespaces. The API key, base extraction prompt and output schema stay unchanged. The full request, including memory, remains subject to the existing 50,000-byte limit and paid-call reservation. Saved budget plans and spent slots are preserved. Editing, saving feedback, disabling a lesson and rebuilding assets make no AI calls.

This is prompt context, not automatic fine-tuning. OpenAI describes task-specific examples and context in its [prompting guidance](https://developers.openai.com/api/docs/guides/prompting). A saved lesson is not evidence that accuracy improved. That requires separately labeled evaluation on new cases. Coordinator corrections must never be substituted into an original model score.

## Verification

The October 12, 2026 checks use synthetic data and fake providers. They verify confirmed resolution, preservation of original evidence, deliberate custom-arrangement approval, pricing and capacity boundaries, immutable feedback history, browser-to-browser saves, stale-edit conflicts, lesson inclusion in the next captured request, disabling a lesson, public/private isolation and preservation of the existing allowance plan. The local browser rehearsal resolves the missing-dietary example with AI disabled.

A later [two-call real-AI comparison](../evaluation/lesson-comparison-v1/README.md) used the same new beverage conversation with and without a saved lesson. Both responses appended notes to the drink option and left the quote blocked. The main check failed in both conditions; this is evidence against claiming that this lesson solved the observed issue.

## Interface reference

The existing EventBrief editor and source inspector are the primary layout and visual references. The supplied CRM reference remains the dashboard direction. The new form follows the Refero copywriting reference: a specific explanation beside the input, one save action, an optional lesson field, and a collapsible audit history. Existing colors, focus treatment and spacing are retained.
